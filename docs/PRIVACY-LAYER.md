# Слой анонимности: что добавляю поверх готового браузера

Это моя часть работы (этап 2). Движок делает Клод; здесь — как анонимность
встаёт поверх него, без переписывания браузера.

Принцип: **сначала браузер, который работает, потом приватность как полиси.**
Ни один пункт ниже не требует менять HTML/CSS/раскладку/растр/JS-движок.

---

## 0. Маршруты (кто и как несёт трафик)

Ось отдельная от уровня приватности: `route.mode` = `direct | chain | bypass |
tor | i2p | proxy` (`sepia route set …`). Уровень приватности задаёт **что**
прячется (куки, JS, диск), маршрут — **кто** это несёт. Комбинируются свободно:
`route=tor` + `privacy=strict` — Tor и чистый браузер; `route=bypass` +
`privacy=normal` — быстрый обход и обычный браузер.

## 1. Уровни

`privacy.level` в `~/.sepia/config.json` (плюс флаг CLI `--privacy`):

| | `normal` | `strict` (по умолчанию) | `paranoid` |
|---|---|---|---|
| Транспорт | цепочка, DoH | цепочка, DoH | цепочка обязательна, `.onion`/`.i2p` только через свой оверлей |
| Killswitch | по флагу `up` | включён | включён, fail-closed без «прямого» исключения |
| Кэш/профиль | диск | память | память |
| Куки | как браузер | только в памяти, партиционированные | выключены |
| JS | включён | включён, песочница без сети/файлов | выключен |
| Внешние ресурсы | все | только same-origin + явный список CDN | только same-origin |
| UA/отпечаток | настоящий | маскируется персоной | маскируется персоной, canvas/audio/WebGL заглушены |
| WebKit-страницы | разрешены | разрешены, но с предупреждением | запрещены (`--no-embed`) |

`normal` нужен, чтобы можно было проверить: «вот браузер как есть, вот что
добавляет приватность». Это ещё и удобный режим для отладки движка.

---

## 2. Точки внедрения (что должно быть в движке)

1. `net::fetch_with` / `net::open_path` — единственный сетевой вход.
   Через него: цепочка, DoH-резолвер, блок-лист, счётчики. Ничего мимо.
2. `storage` — один модуль с путём и режимом (`disk` / `memory` / `off`):
   куки, кэш, профиль, загрузки, закладки.
3. `fingerprint` — одна функция, отдающая значения `navigator`, `screen`,
   `Intl`, UA; движок читает её, персона подменяет.
4. Флаги `js`, `cookies`, `images`, `external_resources`, `embed` в конфиге.
5. `--audit` строится из фактического состояния, а не из текста.

Если чего-то из этого нет — я добавляю это сам, но лучше, чтобы движок уже
держал все сетевые и дисковые операции в одном месте.

## 3. Транспорт

* `chain.hops` — SOCKS5/HTTP, несколько хопов; `on_hop_failure`.
* DoH для прямых соединений; при работе через хоп имя резолвит первый хоп.
* Linux: nftables REDIRECT + `SO_MARK`; macOS: pf; Windows: правила «блок
  дополнения».
* `veil`… то есть `sepia verify` и `selftest` доказывают: прямой запрос
  умирает, через цепочку работает, DNS не уходит системному резолверу.

## 4. Хранилище

* `paranoid`/`strict`: профиль и кэш в памяти, на диск — только закладки
  (явное действие) и явные скачивания.
* `normal`: профиль на диске, как у обычного браузера.
* Переключатель один: `storage.mode`.

## 5. Куки и JS

* `strict`: куки только в памяти, партиционированные по сайту, срок ≤ суток.
* `paranoid`: куки выключены, JS выключен; сайты, которым нужен скрипт,
  показывают оболочку (это осознанная цена).
* `normal`: как есть.

## 6. Отпечаток

* Персона: UA (согласованный с платформой), экран, TZ, языки, canvas/audio
  шум, отсутствие WebGL-строк.
* Для WebKit-страниц — отдельный профиль: там отпечаток диктует WebKit,
  поэтому `strict` предупреждает, `paranoid` запрещает.
* `audit` печатает JA3/UA/экран.

## 7. Проверка (мои тесты)

1. `no_direct_sockets`: загрузка страницы делает ноль соединений мимо
   `fetch_with` (статический скан + тест на счётчиках).
2. `headers_surface`: список заголовков ровно тот, что в аудите.
3. `dns_only_doh`: при `strict` системный резолвер не вызывается.
4. `cookies_memory`: после перезапуска куки пусты; в `paranoid` — не
   создаются.
5. `no_disk_in_paranoid`: профиль/кэш не пишутся, кроме явных действий.
6. `killswitch_holds`: `selftest` на каждой платформе (Linux — контейнер).

---

## 8. Порядок работ

1. Ждём от Клода работающий браузер на целевых сайтах (этап 1).
2. Я включаю `normal`, проверяю, что ничего не мешает движку.
3. Ввожу `strict` по умолчанию, гоняю сайты из приёмки и правлю только
   политики, не движок.
4. `paranoid` — отдельный профиль, документируется как «для чувствительного».
5. Всё, что движок не умеет (например, WebKit-страницы), честно описано в
   `audit` и README.

# QA: как я оцениваю браузер

Роль: тестировщик. Я не пишу движок — я гоняю его по сценариям, ставлю
оценку, ловлю регрессии и отдаю список того, что не работает.

## Что проверяется автоматически (`scripts/qa.py`)

Один сценарий = один сайт и набор проверок. Две правды: текстовая (`--text`)
и пиксельная (`--dump` + анализ PNG).

| Проверка | Что значит | Критична |
|---|---|---|
| exit | процесс завершился без падения | да |
| status | HTTP 200, а не 403/429/CAPTCHA | да |
| текст | количество текстовых узлов ≥ порога | да |
| ссылки | количество ссылок ≥ порога | да |
| визуал | закрашено ≥ 0.4% пикселей (не чёрный/пустой экран) | да |
| цвета | ≥ 12 цветов (не «скелет» из двух серых) | нет |
| контраст | разрыв яркости текста и фона ≥ 18 | нет |
| время | уложился в бюджет сценария | нет |
| слова | ожидаемые фразы присутствуют в выводе | нет |
| клик | попадание в ссылку даёт правильный URL | да (для click-сценариев) |

Оценка: критическая проверка весит втрое; **любой критический провал
ограничивает оценку 70%** — «чёрный экран с 400 текстовыми узлами» больше не
получает 100%.

Запуск:

```bash
python3 scripts/qa.py                       # все сценарии, отчёт в /tmp/sepia-qa
python3 scripts/qa.py --sites github wikipedia
python3 scripts/qa.py --json > /tmp/qa.json
```

Отчёт пишется в `/tmp/sepia-qa/report.json`, рядом — дампы `.png` и вывод
`.txt` для каждого сайта; при повторном запуске печатается дельта к прошлому
прогону. Базовая линия — этот файл: цифры ниже обновляются после каждого
прогона.

## Сравнение с оригиналом (`scripts/visual-diff.py`)

Цель — «точь-в-точь как в оригинале», значит нужен эталон и число. Скрипт
снимает страницу в Chrome (headless, 1200×900, тот же URL), рендерит нашу,
совмещает по лучшему сдвигу и считает: раскладку по блокам 8×8, корреляцию
построчного и поколоночного профиля, долю чернил, расхождение по полосам.
Собирает композит: **эталон | наш | пропало (красное) / лишнее (синее)**.

```bash
python3 scripts/visual-diff.py --url https://en.wikipedia.org/wiki/Web_browser
# → /tmp/sepia-visual/{reference,ours,composite}.png, stats.json
```

Прогон 17 ноября 2026:

| Сайт | Сходство | Раскладка (блоки) | Чернила: эталон / наш | Что пропало |
|---|---|---|---|---|
| example.com | 57.5 | 0.40 | 3.4% / 3.2% | — (метрики шрифта отличаются) |
| Wikipedia | 41.7 | 0.28 | 10.4% / 8.5% | шапка, сайдбар, инфобокс (полосы 75–225, 450–525) |
| GitHub | 37.7 | 0.28 | 26.4% / 13.3% | таблица файлов и колонка About (150–675) |

**Эталон нужно закреплять.** Chrome меняет страницу между прогонами (баннер
пожертвований у Wikipedia, лимиты у HN), поэтому честное сравнение — только
против сохранённого эталона: `--reference /tmp/vd-wiki/reference.png`. Первый
прогон снимает эталон, дальше все сравнения идут с ним, пока сайт не изменился
намеренно.

Порог приёмки для «как в оригинале»: **example ≥ 80, Wikipedia ≥ 60,
GitHub ≥ 55** и ни одной полосы «пропало» выше 2% чернил.

Читать метрику: пиксельный IoU всегда низкий из-за шрифтов; главное —
раскладка (блоки 8×8) и полосы, где у эталона есть содержимое, а у нас нет.
Красное на композите — это и есть список «что чинить», по геометрии.

## Что автоматика не видит (ручной чек-лист)

Проверяется руками в окне, отмечается после каждого прогона:

- [ ] вкладки: новая, закрытие, переключение, восстановление;
- [ ] адресная строка: ввод, поиск, история назад/вперёд;
- [ ] жесты: свайп назад/вперёд, потянуть вниз — обновить;
- [ ] поиск по странице (⌘F) и подсветка;
- [ ] закладки (⌘D) и стартовая страница;
- [ ] скачивание файла ссылкой и ⌘S;
- [ ] формы: ввод текста, кнопка, POST;
- [ ] JS: кнопка с addEventListener и с onclick;
- [ ] видео (когда появится) и звук;
- [ ] тёмная/светлая схема, масштаб окна, retina;
- [ ] падение/ошибка сети: экран ошибки, а не пустота;
- [ ] память и CPU при открытой странице (Activity Monitor).

## Что добавить в автоматику дальше

1. Проверка обрезки справа: пиксели у правого края при GUI-ширине.
2. Сравнение с эталоном (эталонный браузер) по расположению блоков — не
   «похоже», а координаты.
3. Формы: заполнение поля + Enter → ожидаемый URL/POST.
4. JS: сценарий с кнопкой (listener и onclick) и проверка DOM после клика.
5. Диск/куки: после `strict` ничего не появилось на диске (инвариант).
6. Память: RSS после загрузки трёх страниц.

## Правила игры

- Каждая оценка — с датой, сценарием и коммитом, иначе это мнение.
- Регрессия важнее абсолютной цифры: если вчера 100%, сегодня 70% — это
  блокер, даже если «в целом норм».
- Сломанное не переименовывается в «ожидаемое поведение». Список провалов
  уходит Клоду как задачи, а не как жалобы.

### Известные общие дыры

- **Скорость JS (Boa).** Основной бандл YouTube 9,8 МБ исполняется ~11 с;
  Хабр тратит 5–15 с на собственные promise-задачи. Профилирование Boa или
  смена движка — открытое решение. Лимиты на размер сняты по решению
  пользователя; «честного отказа» по размеру бандла нет.
- **CSS Grid:** нет явной расстановки по линиям/именам линий во всей полноте;
  колонки Wikipedia Vector 2022 (сайдбар, «Инструменты») не на месте,
  пустота между шапкой и заголовком ~60 px.
- **Поля ввода** рисуются как кнопки (`[Search]`), без настоящего текстового поля.
- **Нет защиты от бесконечного цикла** (лимит итераций снят): такая страница
  вешает свою вкладку. Тест `runaway_scripts_are_stopped` отключён.
- **Нет страницы-объяснения для блокировок** (403 Cloudflare, 429 Google,
  CAPTCHA) — пока пустой экран.
- **Нет:** Web Workers, `<canvas>`-рисования, WebGL, видео/аудио, WebSocket в
  скриптах, Service Worker, настоящих стримов `fetch` (тело целиком),
  `history`-переходов SPA без перезагрузки — не проверено системно.
- Ширина вёрстки в окне при retina (п. 3 тестировщика) ещё не проверена.

Проверка 13 ноября 2026. **Этап совместимости не принят:** зелёные модульные
тесты и HTTP 200 не означают, что выбранные сайты работают целиком.
Все страницы проходят через HTTP/HTML/CSS/Boa/Layout/Canvas Sepia.
Встроенный WebKit и подмена YouTube сгенерированными страницами удалены.

## Продолжение: устранение зависаний и совместимость DOM

Соединения восстановились. Полный release-прогон после первого набора правок
дал **175 passed, 0 failed, 7 ignored**, без исключения сетевых тестов.
Предыдущие сообщения о недоступной сети ниже — история проверки.

- Добавлен кэш совпадений селекторов только на время одного `Layout::build`.
  Ключ учитывает узел, атрибуты, цепочку предков и viewport; кэш уничтожается
  перед следующим расчётом. Регрессия проверяет изменение `:first-child`
  после изменения соседнего узла.
- Сохранённый GitHub, не рассчитывавшийся за 60 секунд, теперь строится и
  рисуется примерно за **4,18 с**. Это ещё не целевые 150 мс. Живой GitHub
  показывает текст и таблицу файлов: 404 текстовых фрагмента вместо нуля.
- Поддержаны `grid-template-areas`, именованные `grid-area`, строковые области
  в shorthand `grid-template`, области на несколько строк и резервирование
  ячеек до автоматического размещения. Имена линий не создают лишних колонок.
  Это подмножество Grid: полное управление явными строками/линиями ещё впереди.
- Добавлены CharacterData, конструкторы Text/Comment, редактирование данных,
  splitText и сохранение комментариев при разборе/клонировании DOM. Комментарии
  не рисуются, не входят в родительский textContent и не считаются элементами
  в структурных CSS-селекторах.
- `nomodule` теперь выполняется, поскольку ES-модули пока не поддерживаются.
  Диагностика нашла основной скрипт YouTube размером 10,8 МБ, ранее отклонённый
  пределом 4 МБ. Новый предел — 16 МиБ на источник, 32 МиБ на страницу;
  источники не обрезаются посередине. Ограничения отражены в `--audit`.
- Реализован AbortSignal вместо прежнего простого флага: причина отмены,
  событие abort, throwIfAborted, any/timeout и снятие обработчиков, связанных
  с сигналом. Уже отменённый fetch отклоняется до входа в сетевой загрузчик,
  сохраняя причину. Прерывание уже исполняющегося синхронного нативного HTTP
  запроса пока не реализовано; timeout использует существующие грубые таймеры.

Повторная матрица `/tmp/sepia-progress-matrix/report.json`: все 30 процессов
завершились без ошибок соединения, но это **не визуальная приёмка**. Wikipedia
и GitHub читаются с ошибками расположения блоков. Google после стартового
JS-перехода возвращает HTTP 429 с сообщением об ограничении; Яндекс — CAPTCHA.
YouTube до увеличения лимита всё ещё показывал пустую оболочку. Проверка
увеличенного JS-бандла записывается отдельно; его загрузка сама по себе
не подтверждает работу каталога.

Проверка бандла 10,8 МБ: он больше не отбрасывается; JS исполнялся около
11,64 с, процесс потреблял около 700 МиБ в момент наблюдения. Обнаружена и
исправлена следующая отсутствующая возможность — AbortSignal. До её
исправления каталог всё ещё оставался пустым; ошибки webcomponents и
performance.timing требуют дальнейшей работы. Это не готовый YouTube.

Проверка клика средствами самого Sepia (`--click 479,498`, Wikipedia при
1200 px) попадает в ссылку Application software и выдаёт правильный URL
навигации. Это подтверждает конкретное попадание, не весь сценарий браузера.

## Воспроизводимый прогон

```sh
cd browser
cargo test --release --offline
cargo build --release --offline
cd ..
python3 scripts/check-browser-compat.py --out /tmp/sepia-compat
```

Матрица: 5 сайтов × 800/1200/1600 CSS px × прокрутка 0/900, высота 900.
Инструмент сохраняет PNG, stdout/stderr, время и JSON-отчёт. Статусы визуальной
и интерактивной приёмки остаются `pending`, пока их явно не проверит человек.
Артефакты не являются профилем или кэшем браузера.

Снимки исходной версии: `/tmp/sepia-compat-before` (1200) и
`/tmp/sepia-compat-baseline-matrix` (800/1600). Первый повторный прогон:
`/tmp/sepia-compat-after`; он сделан до финальных исправлений CSS и resize.
Эталонные страницы Wikipedia и GitHub просмотрены в обычном браузере.

## Найденные причины и исправления

- Пустые `:is()`/`:where()` перестали превращаться в универсальные селекторы.
  На GitHub такие правила задавали абсолютное позиционирование каждому узлу.
- Кандидаты CSS-каскада индексируются по правому тегу/id/классу. Регрессия
  сравнивает результат с полным перебором правил, включая media и append.
- Flex учитывает рамки/отступы в basis, явный `min-width:0` и повторное
  распределение дефицита ширины после достижения минимумов.
- Разделены `visibility` и прозрачность: поздний `opacity:1` отменяет локальный
  `opacity:0`, но не прозрачность родителя. Частичная opacity ещё не реализует
  полное групповое смешивание CSS.
- HTML поддерживает пробелы вокруг `=`, восстанавливается после лишнего `/`,
  сохраняет незакрытый raw text и правильно обрабатывает title/textarea.
  Начало блочного элемента закрывает незакрытый абзац через inline-потомков.
- CSS защищён от рекурсивных переменных и некорректных Unicode hex-цветов;
  комментарии внутри строк сохраняются.
- Ресурсы неактивных template/noscript больше не загружаются и не применяются
  к активному документу. Это не реализация полной модели HTML template.
- Исправлены detached DOM queries/matches, порядок insertAdjacentHTML,
  события отправки форм, значения submitter и URL-кодирование формы.
- Добавлены реальная передача resize в JS/раскладку, media по высоте и
  изоляция размеров viewport между потоками вкладок.
- Стартовые JS-переходы потребляются загрузчиком: общий сетевой путь,
  ограничение 8 переходов, обнаружение циклов и общий тайм-аут.

## Проверки и измерения

Локальный пример `docs/fixtures/compat.html` объединяет форму поиска,
flex-контролы, textarea, CSS-переменные, ссылку-якорь и обновление DOM.
Новые регрессии расположены рядом с исправляемыми подсистемами.

Замер release-отрисовки окна 2×: около 6,69 мс, преобразование буфера
0,89 мс, repaint тестовой страницы 1,99 мс. Это не замер полного presentation
и не гарантия 60 fps на каждом сайте. `SEPIA_VERBOSE=1` отдельно печатает
время JS и раскладки; CLI `fetched` включает весь путь загрузки.

Во время интеграционной проверки localhost стал недоступен: это воспроизвелось
и независимой Python-парой server/client. Тесты прокси не ослаблены и не
помечены ignored ради зелёного результата. Нужен повтор полного прогона после
восстановления loopback; сетевые настройки и firewall не изменялись.

Предыдущий полный release-прогон: **162 passed, 2 failed, 7 ignored**; оба
падения — сетевые тесты localhost (`media::tests::proxy_refuses_anything_but_connect`,
`page::navigation_tests::youtube_navigation_fetches_origin_page_and_keeps_session`).
После добавления регрессии индекса CSS прогон остальных тестов:
**163 passed, 7 ignored, 2 filtered out**. Это не полный зелёный прогон.

Финальная живая матрица `/tmp/sepia-compat-final/report.json` содержит 30 ошибок
соединения: DoH возвращал Connection reset, независимое TCP-соединение к
1.1.1.1:443 также истекло по тайм-ауту. Эти случаи не засчитываются ни как
визуальная регрессия, ни как успешная совместимость. Результат до восстановления
соединений остаётся непроверенным.

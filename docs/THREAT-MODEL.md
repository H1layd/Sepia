# Модель угроз: от кого защищает и от кого нет

Документ отвечает на один вопрос: **какому противнику схема реально
противопоставлена**, а какому — нет. Всё, что не попало в «защищает», считается
не защищённым.

## Коротко

Схема защищает от **обычной слежки**: провайдера, сайта, рекламных сетей,
локального наблюдателя. От **серьёзного противника** — государственного,
с ресурсами и временем, с контролем над узлами или над машиной — не защищает.

Это не приговор, а граница, за которой нужны другие инструменты (Tor, отдельная
машина, офлайн-дисциплина) либо другой уровень угрозы.

## Защищает

| Противник | Что видит без Sepia | Что видит с Sepia |
|---|---|---|
| Провайдер / локальная сеть | домены через SNI, DNS, IP | только адрес и порт первого хопа; DNS не видит |
| Сайт | ваш IP, куки, отпечаток, Referer | IP выхода; минимальные заголовки; куки в памяти (strict) |
| Рекламная сеть | трекеры, canvas, WebRTC | без WebRTC/canvas, без Referer, куки разбиты по сайту |
| Случайная утечка при сбое | трафик уходит напрямую | killswitch: не разрешено — заблокировано, соединение умирает |
| Тихая поломка защиты | «вроде работает» | `verify`/`selftest`/`--audit` показывают фактическое состояние |

## Не защищает

1. **Глобальный пассивный наблюдатель.** Кто видит вход и выход сразу,
   связывает трафик по объёму и времени. Цепочка из 2–3 узлов это не лечит;
   лечит луковичная маршрутизация с тысячами независимых узлов — это Tor.
2. **Противник, контролирующий узлы.** Если все хопы — ваши VPS (или один
   провайдер), анонимности от него нет: он видит всю цепочку. Схема хороша
   ровно настолько, насколько разнесены и независимы узлы.
3. **Отпечаток браузера.** Собственный движок (Boa, rustls, наш порядок
   заголовков) — **уникален**, значит, толпа маленькая. Подмена UA/экрана/TZ
   этого не скрывает: TLS-отпечаток (JA3/JA4), порядок заголовков, особенности
   JS и вёрстки остаются. Tor Browser силён не «настройками», а миллионами
   одинаковых пользователей; у нас такой толпы нет.
4. **Эксплуатация браузера.** JS и парсеры — поверхность атаки. Уязвимость в
   движке деанонимизирует всё, потому что браузер работает внутри защищённого
   канала. В `paranoid` JS выключен; в `strict` — песочница без сети и файлов,
   но это не аудит и не доказательство безопасности.
5. **Человек.** Логин, куки чужого сайта, стиль, время активности, язык —
   раскрывают лучше любой технической дыры. Это не чинится кодом.
6. **Другие приложения и root.** Killswitch не делает анонимными остальные
   программы; вредонос с root обойдёт фаервол. Защищён только браузер, и только
   пока хост чист.

## Что из этого следует для заявлений

Нельзя писать «анонимность» без оговорки. Правильная формулировка:

> Sepia прячет вас от провайдера, сайта и рекламных сетей за счёт цепочки
> и fail-closed killswitch, и показывает фактическую поверхность через `--audit`.
> От глобального наблюдателя и целевого противника защищает Tor, а не эта схема.

## Что должно быть проверено (и пока не всё есть)

| Проверка | Статус |
|---|---|
| Прямой трафик умирает при killswitch | есть (`selftest`) |
| DNS не идёт системному резолверу | есть частично (`verify`) |
| Нет WebRTC/canvas/Referer | есть в политиках, нет автотеста поверхности |
| Канарейка DNS через цепочку | **нет** |
| UDP/QUIC не утекает | **нет** явного теста |
| Отпечаток TLS (JA3) измерен и описан | есть инструмент (`probe`), нет эталона |
| Порядок заголовков совпадает с описанным | есть тест списка, нет порядка |
| Куки/кэш/профиль не пишутся в `strict`/`paranoid` | **нет** |
| Устойчивость к подмене сертификата | есть (`--insecure` только явно) |

Пустые строки — это работа, а не «сделано». Пока они пустые, `--audit`
не имеет права называть это защитой от чего-то большего, чем обычная слежка.
